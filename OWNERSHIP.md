# KARTA Identity Wallet — Ownership Record

## Proprietary status

KARTA Identity Wallet is maintained as a proprietary project. The original KARTA source code, product architecture, application-specific logic, product documentation, user-interface designs, brand assets and other project-specific materials are intended to remain under the exclusive control of the project owner, except for components expressly identified as third-party materials.

## No implied transfer

Publication, testing, repository access, collaboration, code review, issue participation, pull requests, demonstrations, APK distribution or access to development builds do not by themselves transfer intellectual-property ownership or grant a commercial license to KARTA.

Any future contributor, contractor, employee, studio, agency or development partner should work under written terms that address ownership of deliverables, confidentiality and assignment or licensing of intellectual-property rights before contributing material intended for production use.

## Third-party components

Flutter, Dart packages, native libraries, fonts and other dependencies remain governed by their respective licenses. Third-party rights must be reviewed before every public release. KARTA's proprietary notice applies only to material for which the KARTA project owner holds or controls the relevant rights.

## Release-control principles

1. Production signing keys and Google Play publishing access must remain under accounts controlled by the project owner or an expressly authorized entity.
2. Public releases must not expose private keys, secrets, credentials, production tokens or confidential implementation material.
3. Release builds must preserve user data through documented migration and backup/restore procedures.
4. New external contributors must not be granted ownership merely by repository access or contribution activity; written terms should govern contributions.
5. Brand registration and domain/app-store naming should be checked independently from copyright ownership.

## Evidence preservation

Git history, tagged releases, build artifacts, dated design documents, architecture records, test results and release notes should be retained as development-history evidence.
