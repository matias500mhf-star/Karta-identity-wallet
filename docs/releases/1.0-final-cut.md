# KARTA 1.0 — Final release cut

Run this procedure only after the Phase 1 Build 14 clean-install, encrypted-backup restore and signed Build 13 → Build 14 preservation gates have passed.

The permanent Android keystore remains on an owner-controlled trusted computer. Never upload it or its passwords to GitHub, CI, chat, issues or pull requests.

## 1. Start from the exact approved Build 14 head

Confirm that the approved head has:
- KARTA Security Baseline — PASS
- KARTA API CI — PASS
- KARTA Mobile CI — PASS
- Android Build 14 debug APK — PASS
- physical clean-install acceptance — PASS
- encrypted backup/restore acceptance — PASS
- signed Build 13 → Build 14 update-preservation — PASS
- no release-blocking independent security/privacy finding

## 2. Prepare the deterministic 1.0 cut

From `apps/mobile`:

```bash
python3 scripts/prepare_1_0_release.py
```

Expected result:
- `version: 1.0.0+15`
- final user-facing KARTA 1.0 release label
- no `KARTA Alpha 0.9` release label remains

Do not manually edit additional product behavior during this cut.

## 3. Recreate the Android scaffold and apply KARTA hardening

```bash
flutter create --platforms=android --android-language=kotlin --project-name=karta_wallet --org=com.karta.identity --no-pub .
python3 scripts/install_android.py
flutter pub get
flutter analyze
flutter test
```

The Android patch must enforce API 36+, `allowBackup=false`, `usesCleartextTraffic=false`, KARTA branding and the native document bridge.

## 4. Configure owner-controlled release signing

```bash
export KARTA_KEYSTORE_PATH='/OWNER-CONTROLLED-PATH/karta-upload.jks'
export KARTA_KEY_ALIAS='karta-upload'
export KARTA_KEYSTORE_PASSWORD='...'
export KARTA_KEY_PASSWORD='...'

python3 scripts/configure_release_signing.py
```

Use the same permanent signing identity that preserved the Build 13 → Build 14 update path.

## 5. Build final APK and AAB

```bash
flutter build apk --release
flutter build appbundle --release
```

## 6. Verify final APK identity

```bash
python3 scripts/verify_release_artifact.py \
  build/app/outputs/flutter-apk/app-release.apk \
  --expected-version-code 15 \
  --expected-version-name 1.0.0
```

Require `RELEASE GATE: PASS`.

Verify the signed AAB separately:

```bash
python3 scripts/verify_release_bundle.py \
  build/app/outputs/bundle/release/app-release.aab
```

Require `RELEASE GATE: PASS` for the AAB as well.

Record:
- commit SHA;
- APK SHA-256;
- AAB SHA-256;
- permanent certificate SHA-256;
- device used for final smoke test.

## 7. Final smoke test

Install the final signed APK on a test device and confirm:
- PIN;
- biometric unlock;
- encrypted document/PDF open;
- validity metadata;
- QR/share;
- local encrypted backup and restore;
- privacy screen;
- account/backup online flow only if production online service is enabled.

## 8. Google Play

Before production rollout:
- confirm privacy-policy URL is live;
- confirm external account-deletion URL is live;
- reconcile Data Safety with the exact signed AAB and its SDKs;
- confirm content rating, target audience and ads declarations;
- configure Google Play App Signing and owner MFA/recovery;
- upload to internal/closed testing first;
- review Play pre-launch report and Android Vitals;
- promote to production only if there is no release-blocking finding.

No feature development belongs in this cut. Non-blocking improvements move to 1.0.x or 1.1.
